# Triage Labels

The `triage` skill speaks in **waiting states**. This file maps them to the label strings
used in Linear (team Eng / `VETTA`).

A label is a claim about what the ticket **waits for** — never about what anyone is
currently doing to it. An untriaged ticket is **unlabeled, in state Backlog**.

| Label               | The ticket waits for                                              |
| ------------------- | ----------------------------------------------------------------- |
| `ready-for-agent`   | Nothing. An AFK session can start from the attached brief.         |
| `ready-for-human`   | Human execution. The brief is complete, but a step needs a person. |
| `needs-human-input` | One reply. A decision card is posted; answer it from your phone.   |
| `needs-grilling`    | A session. The open questions are entangled; an agenda is posted.  |

These four are the whole vocabulary. The old five-role default table — `needs-triage`,
`needs-info`, `wontfix` alongside the two that survived — retired with the plan loop, and
those labels no longer exist in Linear. Never create or apply them.

Labels are **team-scoped**, so team Eng shares one label set across every project on the
board — the same `ready-for-agent` serves the To-do App, Kale, Poverty Stoplight and
Agents. All four already exist, so triage never needs `create_issue_label`.

## How tickets get triaged

A morning cron on the Mac mini (see the `Kale-BI/kaley-agent` README, "Backlog triage
cron") sweeps unlabeled Backlog tickets across all active projects daily at 07:30
Europe/London: one fresh agent session per ticket, a label plus a brief, card, or agenda
on the ticket, and a digest in Slack whose thread takes `@kaley` replies. Triage writes
attribute as the **Symphony** app user and open with "Generated by AI during triage."
Running `/triage` by hand still works anytime.

Because the label is applied at the end of the loop, a session that dies leaves the
ticket unlabeled and the next sweep retries it.

## Dispatch

Labels never dispatch anything. `ready-for-agent` marks a ticket approved for autonomous
work; the lever is Symphony's own — **delegate the issue to the Symphony agent and move
it to Todo**. Delegation is applied at dispatch time, not kept as standing state on
waiting tickets.

## Labels outside the waiting states

- `yolo` — human-applied standing preflight authorization, defined in `kale-app`
  ADR 0020. An agent never applies it, to any issue.
- `preview` — this issue's pull request needs a deployed preview origin.
- `psp-families`, `psp-data-platform` — workstream tags on the Poverty Stoplight board.
- `wayfinder:*` — wayfinder maps and their decision tickets. The triage sweep skips them:
  a map manages its own children.
